# v1.1.0-rc.1 release notes (pre-release)

Tagged as a pre-release candidate after the owner approved merging and proceeding; not a stable release.

## Highlights
- 23 distinct workflows (was clones), `new-product-development` still the full 190-stage journey.
- Every stage has a RACI; all 74 roles own at least one stage; role contracts are derived, not templated.
- Skills use the Anthropic authoring format; near-duplicate Markdown pairs at 0.80+ fell from 197 to 7.
- 121 stages have real content; 69 are honest stubs.
- CI blocks on duplicates, unresolved references, orphans, broken links and tests.

## Breaking changes
Registry files renamed `*.yaml` to `*.json`; `registry/WORKFLOW_REGISTRY.json` is replaced by `registry/workflows/*.json`;
skill frontmatter `name` is now the skill id. See `CHANGELOG.md`.

## Known limitations
- 69 of 190 stages are stubs. 21 stages are named by scenario tests; those check structure, not execution.
- No model eval has been run (`evals/`). No platform adapter has been tested (`adapters/COMPATIBILITY.md`).
- 7 role-contract pairs are between 0.80 and 0.85 similar; 8 roles own only one stage (`docs/audit/ROLE_DECISIONS.md`).
- Validation commands in stage content are examples and have not been run against a real project.
