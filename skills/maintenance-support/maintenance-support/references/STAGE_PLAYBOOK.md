# Service maintenance and customer support — Stage Playbook

> Generated from the canonical stage registry. Use the parent skill first, then load only the relevant stage entry.

## 167. L1 Support

**Purpose:** maintain a live service safely and preserve customer continuity

**Procedure:**
- Classify severity, affected customers, workaround and escalation path using support policy.
- Reproduce against the affected version; correlate logs, metrics and recent changes without exposing customer data.
- Implement the smallest safe correction or maintenance action with regression and compatibility coverage.
- Communicate workaround/fix version, verify closure and update runbook or knowledge base.

**Inputs:** support case or maintenance request, affected versions and customer impact, service ownership and change policy
**Artifact:** support/maintenance record
**Verification:** Service owner acceptance and customer-facing closure check.
**Handoff:** Transfer support/maintenance record with source/revision, validation evidence, owner, limitations, unresolved risks and the next decision to the downstream role.

## 174. Performance Optimization

**Purpose:** improve measured performance without violating correctness

**Procedure:**
- Profile before changing code; identify dominant cost and reproducible baseline.
- Choose cache key, TTL, invalidation and consistency behavior based on data semantics.
- Bound memory, stampede, stale data and eviction behavior.
- Compare before/after p50/p95/p99, throughput, error rate and cost under equivalent load.

**Inputs:** baseline workload and latency profile, consistency/freshness requirements, resource and cost limits
**Artifact:** profile report
**Verification:** Performance and correctness regression review.
**Handoff:** Transfer profile report with source/revision, validation evidence, owner, limitations, unresolved risks and the next decision to the downstream role.
